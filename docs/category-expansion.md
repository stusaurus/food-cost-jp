# 食品マルシェのカテゴリ拡張（2026-10-02）

## 実データ調査

公開カテゴリを変更する前に、GitHub Actions内で楽天APIを2回調査した。初回のカレーにはご飯付きセット、袋麺にはうどんとアソート、数量表記には「550g 6袋 12袋」が混ざっていた。検索と除外を絞り、掛け算記号なしの外箱数を勝手に乗算する挙動を除いた。

第2回取得後、最終数量判定で再検査した送料込み候補：水10、パスタ24、グラノーラ21、カレー11、袋麺12、カップ麺13。値は調査時点であり、毎日の取得数は固定しない。袋麺の「5P×2個」は食数を一意に確定できないため除外した。

## 公開基準と対象

- 新カテゴリは送料込み候補3件以上のときだけトップとFinderに出す。
- 3件未満のカテゴリページはnoindex,follow。sitemapからも外す。
- 既存4カテゴリのURLと数量解析は維持。新カテゴリは独立したfail-closed解析を使う。
- ミネラルウォーター：無味・非炭酸。1L / 1本。
- パスタ：乾燥スパゲッティ系。100g / 1kg。ソース・冷凍・生・ギフト除外。
- グラノーラ：一般シリアル全体とは混ぜない。100g / 1kg。バー・プロテイン除外。
- カレー：ご飯なしの1食用レトルト、100〜350g。1食 / 100g。
- 袋麺：スープ付き即席袋ラーメン。1食。うどん・生麺・麺のみ・アソート除外。
- カップ麺：通常サイズのカップラーメン。1食。ミニ・大盛り・うどん・焼きそば・曖昧セット除外。

## 体験と計測

4売り場（ごはん・主食、飲みもの、朝食・シリアル、ストック食品）を編集的な2列に配置し、スマホでは縦にする。各売り場に写真・説明・掲載数・コンパクトな入口を配置。Heroと既存イラスト、生成り、深緑、紙の値札は維持。

Finderは売り場の折りたたみから食品を選ぶ。相談の4買い方は維持。横断棚はカテゴリごとに1候補を選び、異なる単価を順位付けしない。カテゴリが増えても写真棚は横に歩ける構成にして高さを抑える。

保存のカテゴリ・比較単位は共通定義から生成する。新カテゴリも同じsave / compare / affiliateイベントを使用する。market_shelf_viewには単一カテゴリの場合そのID、横断時はallとcategory_idsを記録する。GA4送信内容はUIテストで検査する。GA管理画面での受信は別途確認が必要。

optimization-report.jsonには各カテゴリの取得・正規化・掲載・送料不明・除外理由と履歴蓄積率を含める。新カテゴリの初日は履歴蓄積中として扱い、架空の値下がりは作らない。

## 次の候補（未実装）

構造面での事前検討：小麦粉・ホットケーキミックス・もち・乾燥わかめは重量単位を明示しやすい。そうめん・乾麺うどん・そばは各々独立カテゴリとし、つゆ付き・生・冷凍を除外する必要がある。ツナ缶は固形量と内容総量、スープは濃縮・粉末・完成品と1食量、コーンフレークはグラノーラとの分離を先に定義する必要がある。

今回はこれらの楽天実データ掲載可能数を検証していないため追加しない。次回も取得→数量・タイプ検証→安全な送料込み候補の確認を行ってから公開する。

## 公開経路

実際のPages設定はmain/rootのブランチ公開だった。独自deploy-pagesとブランチ公開が同時に走り、片方が400 in progress deploymentで失敗していた。既存設定を保ち、Actionsの品質検査→生成物コミット→ブランチPages公開へ経路を統一した。
